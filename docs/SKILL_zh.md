# 商店图

商店图是用户几秒内决定"要不要点进来"的依据。好的商店图只做两件事：让人看懂这个 App 能给他什么，并相信它说的是真的。

## 核心原则

**在真实展示产品的前提下，让用户发现它对自己的价值。**

用户在商店里只花几秒扫过，心里只问一件事：这对我有什么用？

- **先认出自己。** 具体的生活时刻比抽象的功能描述更容易让人觉得"说的是我"。这是共鸣，也是入口。
- **再看见价值。** 让他看到自己的需求被满足的那一刻：输入一句话，得到一个能直接用的结果。价值要让人"看见"，而不是被告知。文案和焦点负责这两步。
- **价值必须可信。** 靠真实。画面里的界面和数据，都是 App 真的做得到的；聚焦核心体验，不夸大，不借用无法验证的东西（奖项、编造的数字）。设备、光影、背景只是衬托，不抢戏，不显得夸张。

真实是前提，不拿来和好看交换。一张图只讲一件事。搜索结果里最多只露出前三张，很多人不会看到后面的图，所以前三张要讲清最核心的价值，每张自己也要完整。

## 开始前

向用户确认三件事（已经知道的不再问）：

- 产品一句话，以及它给用户的核心价值
- 品牌性格：安静、人文，还是高能、工具型（决定后面每层的倾向）
- 可用素材：真实界面截图、参考图

有参考图时，先把它拆成两半：**它在做的事**（建立信任？讲定位？展示功能？）和**它的样子**（排版、配色、字体）。保留前者，样子按自己的品牌重画，不照搬。

## 工作方式

每一层都这样走：给出 2–3 个方案并排展示（在 Figma 里并排做出来），标出推荐和理由 → 用户选 → 记入规范表。判断方案好坏只问一句：它是否更真实地展示了产品，是否更能让人发现价值？

先定全套规则，再做单张变化。新方案放新的 frame，不覆盖用户已定稿的。

先弄清这套图要讲的故事：一张图只讲一件事，整套按「是什么 → 怎么用 → 得到什么 → 为什么信」排顺序。

## 五层框架

```
┌──────────────────────────────────────────────┐
│  1. 文案层：超大主标 + 1句副标（价值/场景，非功能）│
├──────────────────────────────────────────────┤
│  2. 焦点层：核心卡片/气泡突出（破框放大 / 屏幕内高亮）│
├──────────────────────────────────────────────┤
│  3. 设备层：钛金属微壳 / 无边框屏幕 / 微倾斜视角  │
├──────────────────────────────────────────────┤
│  4. 光影层：环境微阴影 / 局部投影 / 底部漫反射光   │
├──────────────────────────────────────────────┤
│  5. 背景层：连版跨屏 / 暖纸肌理 / 弥散渐变 / 品牌色 │
└──────────────────────────────────────────────┘
```

每张图都按这五层从上到下检查。每层先定全套统一的规则，再定单张的变化。下面每一层给出几种方案，供用户选择。

### 1. 文案层：这张图要让人记住哪一句话？

| 方案 | 效果 | 适合 |
|---|---|---|
| 价值句 | 直接说得到什么 | 新 App，需要立刻讲清价值 |
| 场景句 | 点出一个具体时刻 | 产品绑定生活场景 |
| 动作句 | 用户的动作加结果 | 操作路径简单，一句话说得完 |

主标两行以内，讲价值或场景，不讲功能名；副标补上主标没说的那一半；文字用来增强画面，不是描述画面。整套主标的关键词不重复；每个语言版本要单独成立。

### 2. 焦点层：先看哪里？

先选主角：能证明主标的那一个真实界面模块。再选强调的强度：

| 方案 | 效果 | 适合 |
|---|---|---|
| 破框放大 | 主角放大浮出设备，抓眼 | 高能、工具型；单张主打 |
| 屏幕内高亮 | 不破框，只用浅底色加细描边轻轻标出 | 安静、人文；追求可信与统一 |
| 无强调 | 只靠文案引导 | 界面本身已经足够清楚 |

全套只选一种。每张只有一个主角；放大的元素必须是界面里真实存在的，按原位对齐。

### 3. 设备层：设备要不要被看见？

| 方案 | 效果 | 适合 |
|---|---|---|
| 无边框屏幕 | 圆角加阴影，设备退到后面 | 界面是主角（默认推荐） |
| 微壳 | 带薄薄的机身 | 需要"这是手机里的 App"的语境 |
| 微倾斜 | 带一点透视 | 追求动感，且全套都这样 |

全套统一屏幕宽度、左右边距、顶部位置、圆角、出血方式。不放第二台手机。

### 4. 光影层：前后层级读得出来吗？

| 方案 | 效果 | 适合 |
|---|---|---|
| 仅轻阴影 | 设备和主角只带一层柔和阴影 | 克制的品牌（默认推荐） |
| 单光源投影 | 所有投影同一方向，层次更明显 | 有破框元素时 |
| 加底部漫反射光 | 增加氛围 | 品牌需要更暖或更有氛围 |

全套一套参数，同一光源。光影只是增强层级，去掉后层级依然要读得出来。

### 5. 背景层：整套是一个家族，单张也成立吗？

| 方案 | 效果 | 适合 |
|---|---|---|
| 品牌色或纸面纯色 | 干净、统一 | 默认推荐 |
| 连版跨屏 | 滑动时连成一幅 | 想要整体感，但每张单看也必须成立 |
| 弥散渐变 | 柔和有层次 | 品牌本身偏渐变 |

先把五张并排、同一内容不同背景各做一行再定。只看前三张时也要成立。

## 首图

| 方案 | 效果 | 说明 |
|---|---|---|
| 产品首图 | 标题加真实界面 | 一眼知道产品是什么（默认推荐） |
| 品牌封面 | logo、大标题、价值标签，不放界面 | 品牌感强，但占着最显眼的位置却看不到界面，后面几张要撑起"真实使用" |

Apple 要求截图展示 App 正在使用，整套里至少多数张要是真实界面。

## 素材

需要真实界面时，让模拟器或开发 agent 造数据并截图，不手画假界面。同一数据（分类名、计数、词条）在多张图里必须来自同一份。不展示未上线的功能入口、调试标记、空态、加载中或无法验证的说法。

## 规范表

每层选定后填一行，作为全套的唯一依据：

| 层 | 选择 | 具体值 |
|---|---|---|
| 文案 | | 主标 / 副标的字号、位置、行数 |
| 焦点 | | 主角、强调样式 |
| 设备 | | 宽度、边距、顶部位置、圆角、出血 |
| 光影 | | 阴影参数 |
| 背景 | | 色值或做法 |
| 禁止 | | 本套不允许的做法 |

## 导出尺寸

按 [Apple 截图规格页](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications) 中标为**必需**的尺寸导出。规格会更新，不在这里写具体数字。

设计稿画布 = 目标像素 ÷ 3，按 @3x 导出；导出前隐藏标注层。

## 交付前自查

- [ ] 每层的选择与规范表一致，五张并排看没有跳动
- [ ] 遮住 logo 只读文案，能说出这个 App 给我什么
- [ ] 每张只有一个主角
- [ ] 跨图数据一致；没有未上线功能、调试标记、空态、无法验证的说法
- [ ] 只看前三张时依然成立
- [ ] 导出尺寸是规格页上标为必需的尺寸，标注层已隐藏
