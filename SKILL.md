# App Store Screenshots

Screenshots are what a person uses to decide, in a few seconds, whether to tap into your app. A good set does two things: it makes clear what the app gives them, and it makes them believe it.

## Core principle

**While showing the product honestly, let the user discover what it is worth to them.**

Someone scanning the store spends a few seconds and asks one question: what is this good for me?

- **First, recognize themselves.** A specific moment from their own life feels more like "this is about me" than an abstract feature description. This is resonance, and it is the way in.
- **Then, see the value.** Show the moment their need is met: they type one sentence and get a result they can use right away. Value should be seen, not announced. Copy and focus do these two jobs.
- **The value must be believable.** That comes from being real. Every screen and every piece of data shows something the app can actually do. Stay on the core experience, don't exaggerate, and don't borrow trust you can't verify (awards, invented numbers). Device, light and shadow, and background only support the content; they should not compete with it or feel showy.

Honesty is the premise, and it is never traded for looking good. One image says one thing. Search results show at most the first three screenshots, and many people never see the rest, so the first three must carry the core value, and each must be complete on its own.

## Before you start

Confirm three things with the user (skip what you already know):

- The product in one sentence, and the core value it gives people
- The brand's character: quiet and humanist, or energetic and tool-like (this leans every layer's choice)
- Available material: real screens, reference images

If there is a reference image, split it in two first: **what it is doing** (building trust? stating positioning? showing a feature?) and **what it looks like** (layout, color, type). Keep the first, redraw the second in your own brand. Don't copy it.

## How to work

Every layer goes the same way: show 2–3 options side by side (build them next to each other in Figma), mark a recommendation with the reason → the user picks → record the choice in the spec table. Judge options with one question: does this show the product more honestly, and does it help people discover the value more easily?

Set the rules for the whole set first, then vary individual images. Put new options in a new frame; never overwrite what the user has finalized.

Settle the story first: one image says one thing, and the set follows the order "what it is → how to use it → what you get → why to trust it".

## The five layers

```
┌──────────────────────────────────────────────────────────┐
│  1. Copy:        a large headline + one subline          │
│                  (value or scene, not feature names)     │
├──────────────────────────────────────────────────────────┤
│  2. Focus:       the key card or bubble stands out       │
│                  (break the frame / highlight on-screen) │
├──────────────────────────────────────────────────────────┤
│  3. Device:      thin titanium bezel / edge-to-edge      │
│                  screen / slight tilt                    │
├──────────────────────────────────────────────────────────┤
│  4. Light:       soft ambient shadow / local drop shadow │
│                  / diffuse glow at the bottom            │
├──────────────────────────────────────────────────────────┤
│  5. Background:  panoramic spread / warm paper texture / │
│                  diffuse gradient / brand color          │
└──────────────────────────────────────────────────────────┘
```

Check every image against these five layers, top to bottom. For each layer, set one rule for the whole set first, then decide how individual images vary. Each layer below offers a few options for the user to choose from.

### 1. Copy: which sentence should this image make them remember?

| Option | Effect | Fits |
|---|---|---|
| Value line | States what you get, directly | A new app that must explain its value at once |
| Scene line | Points to one specific moment | A product tied to everyday situations |
| Action line | The user's action plus its result | A simple flow that fits in one sentence |

Headline: two lines at most, about value or scene, never a feature name. Subline: add the half the headline left out. Use words to strengthen the picture, not to describe it. No repeated keywords across headlines in the set. Each language version must stand on its own.

### 2. Focus: where should the eye go first?

Pick the hero first: the one real interface module that proves the headline. Then pick how strongly to emphasize it:

| Option | Effect | Fits |
|---|---|---|
| Break the frame | The hero is enlarged and floats out of the device; eye-catching | Energetic, tool-like brands; a single standout image |
| Highlight on-screen | No frame-breaking; a light tint and a thin outline mark it quietly | Quiet, humanist brands; trust and consistency |
| No emphasis | Let the copy do the guiding | The interface is already clear enough |

Choose one approach for the whole set. One hero per image. An enlarged element must exist in the real interface and sit aligned with its original position.

### 3. Device: should the device be noticed?

| Option | Effect | Fits |
|---|---|---|
| Edge-to-edge screen | Rounded corners and a shadow; the device steps back | The interface is the hero (default) |
| Thin bezel | A slim physical frame | You want the "this is an app on a phone" context |
| Slight tilt | A touch of perspective | You want motion, and the whole set does it |

Keep screen width, side margins, top position, corner radius and bleed identical across the set. Don't show a second phone.

### 4. Light and shadow: can the front-to-back order be read?

| Option | Effect | Fits |
|---|---|---|
| Soft shadow only | One gentle shadow on the device and hero | Restrained brands (default) |
| Single light source | Every shadow falls the same way; clearer depth | When something breaks the frame |
| Add a bottom glow | More atmosphere | The brand wants to feel warmer or richer |

One set of parameters and one light source for the whole set. Light and shadow only reinforce depth; with them removed, the order must still read.

### 5. Background: does the set feel like one family, and does each image still work alone?

| Option | Effect | Fits |
|---|---|---|
| Solid brand color or paper | Clean and unified | Default |
| Panoramic spread | Images join into one picture as you swipe | You want a sense of the whole, but each image must still work alone |
| Diffuse gradient | Soft and layered | The brand itself leans gradient |

Lay the five images side by side and try each background in its own row before deciding. The first three images must also work on their own.

## The first image

| Option | Effect | Note |
|---|---|---|
| Product first | A headline plus a real screen | You know what the product is at a glance (default) |
| Brand cover | Logo, big headline, value tags; no screen | Strong brand feel, but it takes the most visible slot without showing the app, so the following images must carry the "real use" |

Apple expects screenshots to show the app in use. At least most images in the set should be real screens.

## Material

When you need real screens, have the simulator or a development agent create the data and capture it. Don't hand-draw fake interfaces. The same data (category names, counts, entries) must come from one source across images. Don't show unreleased entry points, debug markers, empty states, loading states, or claims you can't verify.

## Spec table

Fill in one row per layer once it is chosen. This is the single source of truth for the set:

| Layer | Choice | Specifics |
|---|---|---|
| Copy | | Headline / subline size, position, lines |
| Focus | | Hero, emphasis style |
| Device | | Width, margins, top position, corner radius, bleed |
| Light | | Shadow parameters |
| Background | | Color value or approach |
| Not allowed | | What this set must not do |

## Export size

Export at the size marked **required** on [Apple's screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications). The specification changes, so no numbers are written here.

Design canvas = target pixels ÷ 3, exported at @3x. Hide annotation layers before exporting.

## Final check

- [ ] Each layer's choice matches the spec table; the five images side by side show no jumps
- [ ] With the logo covered, the copy alone says what this app gives me
- [ ] Every image has one hero
- [ ] Data is consistent across images; no unreleased features, debug markers, empty states or unverifiable claims
- [ ] The first three images work on their own
- [ ] The export size is one marked required on the specification page, and annotation layers are hidden
